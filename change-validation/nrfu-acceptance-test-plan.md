# NRFU Acceptance Test Plan — Generated, Executed, and Signed Off

Turn a network design into a network-ready-for-use (NRFU) acceptance battery — generated by the agent, executed on real NOS devices, delivered as an evidence report.

## The Prompt

Copy this into [NetPilot](https://app.netpilot.io):

> Build this design as a lab, then generate and execute an NRFU acceptance test plan against it: a dual-hub DMVPN WAN — two Cisco IOL hubs, four spokes, OSPF inside the tunnels, HSRP pairing hub-1 (active, priority 110, preempt) with hub-2 at the head end. Derive the test plan first and show it to me before executing: (1) interface and tunnel state on every device, (2) expected OSPF adjacencies and their count, (3) the routing table each spoke should hold, (4) a full spoke-to-spoke and spoke-to-hub reachability matrix, (5) failover — shut hub-1 and measure reconvergence time and packet loss with continuous probes running, (6) a 200 Mbps iperf3 baseline from each spoke to the hub site. Then execute every case and give me a pass/fail report with the command output as evidence for sign-off.

## What You'll Build

- 2 Cisco IOL DMVPN hubs (HSRP active/standby) + 4 spoke routers
- An agent-derived, editable NRFU test plan across six assertion layers
- Executed reachability matrix, failover measurement, and per-spoke throughput baselines
- A sign-off-ready pass/fail report with command-level evidence

## Concepts Demonstrated

- NRFU (network ready for use) — proving actual operating state matches the design before production traffic
- The six layers of an acceptance test plan: interfaces, adjacencies, routing state, reachability, failover, baselines
- Deriving test cases from a design instead of filling a spreadsheet template
- Measuring convergence with in-flight probes, not just checking neighbor state afterward
- Rehearsing the acceptance battery on a lab mirror before running it against the real deployment

## Vendors Used

- Cisco IOL (6 routers)
- Linux (test hosts for probes and iperf3 baselines)
